# oauth-authentication Specification

## Purpose

Enable OAuth 2.0 login (GitHub first) alongside email/password auth. Define provider
abstraction, identity resolution, token persistence, and identity management UI.

## Requirements

| #   | Requirement                                                                                                                                                                                                                                                          | RFC 2119 | Scenarios                                                                                                                                                                                                              |
| --- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| R1  | **Provider Interface**: `ExternalIdentityProvider` in domain layer with `getAuthorizationUrl(state, redirectUri)`, `exchangeCode(code, redirectUri)` → `ExternalUserProfile { id, email, displayName, avatarUrl, accessToken, refreshToken }`, `getProviderName()`.  | MUST     | S1: GitHub adapter fulfills contract. S2: Future provider (e.g. GitLab) registers via `ProviderRegistry` — OAuth controller routes without changes.                                                                    |
| R2  | **Authorization Endpoints**: `GET /api/v1/auth/oauth/:provider` (redirect) and `GET /api/v1/auth/oauth/:provider/callback` (callback). Both `@Public()`. Redirect sets CSRF `state` as signed JWT. Callback validates `state` before code exchange.                  | MUST     | S1: Happy path — click "Sign in with GitHub" → redirect to GitHub → callback resolves identity → JWT issued via `buildAuthResponse` → redirect to `/?oauth=success`. S2: Tampered `state` → 400 `INVALID_OAUTH_STATE`. |
| R3  | **Identity Resolution**: 1) Match `external_identities` by `(provider, external_id)` → existing user. 2) No match: lookup `User` by email → link identity. 3) No email match: auto-provision `User` with `isEmailVerified=true`, link identity. All paths issue JWT. | MUST     | S1: Returning user → identity match → JWT, no re-link. S2: Existing email/password user, first OAuth login → identity linked to user. S3: Brand-new user → auto-provision `User` + `ExternalIdentity` + JWT.           |
| R4  | **External Identity Table**: `external_identities(id UUID, userId FK→users, provider, externalId, accessToken encrypted, refreshToken encrypted nullable, tokenExpiresAt nullable, createdAt, updatedAt)`. Unique `(provider, externalId)`.                          | MUST     | S1: Duplicate `(provider, external_id)` → 409 `IDENTITY_ALREADY_LINKED`.                                                                                                                                               |
| R5  | **Provider Login UI**: Login and register pages SHALL render "Sign in with GitHub" button when `GITHUB_CLIENT_ID` env var is set, separated by divider from email/password form.                                                                                     | SHALL    | S1: `GITHUB_CLIENT_ID` set → button visible. S2: Env var absent → no provider buttons.                                                                                                                                 |
| R6  | **Frontend OAuth Flow**: `AuthContext` exposes `loginWithProvider(provider)` redirecting to `/api/v1/auth/oauth/{provider}`. Root page detects `?oauth=success` query param and calls existing session restore.                                                      | MUST     | S1: Click button → `loginWithProvider('github')` → redirect → callback → session restored from JWT in localStorage.                                                                                                    |
| R7  | **Identity Management (Settings)**: Settings > Security SHALL list linked identities with provider name, display name, and Unlink button. Unlinking the last auth method (no password set) SHALL be prevented.                                                       | SHALL    | S1: Authenticated user sees "GitHub — octocat" with Unlink button. S2: Sole identity (no password) → unlink → 400 `CANNOT_UNLINK_SOLE_IDENTITY`.                                                                       |
| R8  | **Token Encryption**: OAuth access/refresh tokens MUST be encrypted at rest via AES-256-GCM using key from `AUTH_TOKEN_ENCRYPTION_KEY`. Tokens MUST NOT appear in logs or API responses.                                                                             | MUST     | S1: After code exchange, `accessToken` column contains ciphertext, not plaintext. S2: `GET /api/v1/auth/me` response excludes `accessToken`.                                                                           |
| R9  | **Backward Compatibility**: Existing endpoints (`POST /api/v1/auth/register`, `login`, `refresh`, `logout`) and `AuthResponse` shape remain unchanged.                                                                                                               | MUST     | S1: Email/password login returns `{ accessToken, refreshToken, expiresIn, user }` identical to pre-OAuth format.                                                                                                       |
